该 Flutter UI 组件库在错误处理方面采用**轻量级、结果对象化**的策略，未定义统一的异常类型或全局错误码体系，而是针对具体业务场景（尤其是文件上传）使用 `UploadResult` 结果对象和 try-catch 捕获进行错误传播。

## 核心模式

### 1. 结果对象化错误（UploadResult）
在 `lib/src/file_upload/model/upload_config.dart` 中定义了 `UploadResult` 类，通过 `success` 布尔字段和可选的 `error`/`data` 字段统一表示成功或失败状态：
- 成功：`UploadResult.success(data: {...})`
- 失败：`UploadResult.failure(error: '错误信息')`
- 从原始响应解析：`UploadResult.successFromRaw(rawBody)`

### 2. 分层异常处理
- **服务层** (`upload_service.dart`)：使用 `try-catch` 捕获 `SocketException`、`HttpException` 等网络异常，转换为友好的错误消息字符串
- **控制器层** (`upload_controller.dart`)：包裹自定义上传函数调用，捕获任意异常并转为 `UploadResult.failure`
- **工具层** (`file_utils.dart`)：对 HTTP 请求使用 try-catch 返回 `null` 表示失败，而非抛出异常

### 3. UI 组件的错误降级
在 `select_modal_content.dart` 中，远程搜索失败时通过 `catch (_) { ... }` 捕获异常，将 `_isLoading` 设为 false 并清空结果列表，保持 UI 稳定性。

## 设计决策

- **不抛异常原则**：UI 组件避免抛出异常，通过回调和状态变化通知上层
- **错误信息字符串化**：所有错误最终都转换为可读的字符串消息
- **渐进式降级**：JSON 解析失败时保留 null 值而非中断流程
- **调试友好**：大量使用 `debugPrint` 记录关键步骤和错误信息

## 开发者约定

1. 异步操作应返回结果对象而非抛出异常
2. UI 组件内部捕获所有异常，确保界面不会崩溃
3. 网络相关错误应区分 Socket 异常和 HTTP 异常
4. 使用 `debugPrint` 替代日志框架进行开发调试
5. 错误信息应包含足够的上下文以便定位问题
