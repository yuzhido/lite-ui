该 Flutter 组件库在错误处理方面采用**轻量级、声明式**的策略，没有统一的异常类型体系或全局错误中间件，而是根据场景选择合适的处理方式：

### 1. 参数校验使用 `assert`
- 组件构造函数中广泛使用 `assert` 进行入参合法性校验，如 `dropdown_choose.dart`、`select_modal_content.dart`、`file_upload.dart`、`clear_icon.dart` 等。
- 断言失败时抛出 `AssertionError`，用于开发阶段快速发现调用方传入非法参数。

### 2. 异步操作使用 try-catch 捕获异常
- 按钮点击回调（`action_button.dart`）通过 `try/finally` 包裹异步执行，确保 loading 状态正确恢复。
- 远程搜索（`select_modal_content.dart`）在 `onRemoteSearch` 调用时使用 `try/catch`，异常时降级为空结果并重置加载状态。
- JSON 解析（`upload_config.dart`）对 `jsonDecode` 使用 `try/catch`，解析失败时返回 null 而非抛错。

### 3. 业务错误通过返回值表达
- **UploadResult**（`upload_config.dart`）：使用 `success` + `error` 字段表示上传成功/失败，配合 `UploadResult.success()` / `failure()` 工厂方法创建结果对象。
- **EmptyDataType**（`empty_data/models/index.dart`）：用枚举区分空状态场景（empty/search/noNetwork/error/noPermission/noMessage/noOrder/maintenance），由 UI 层渲染对应提示。
- **DialogPresetIcon**（`dialog_action/models/index.dart`）：用 success/warning/error/info 预设图标表达弹窗状态。

### 4. 无全局错误处理机制
- 未发现自定义 Exception/Error 类继承体系。
- 未使用 `catchError`、`onError` 等全局异常拦截。
- 未使用 `printStackTrace`、日志框架记录错误堆栈。
- 未使用 `panic/recover` 模式（Flutter/Dart 不适用）。

### 5. UI 层错误展示
- 下拉选择器通过 `state.errorText` 和 `LiteUITheme.of(context).errorColor` 显示验证错误文本。
- 空状态组件提供专门的 error 类型，以统一视觉风格展示加载失败。
- 弹窗组件支持 error 预设图标，快速传达错误语义。

### 开发者应遵循的约定
1. **参数校验**：在组件构造函数中使用 `assert` 检查必填项和互斥参数。
2. **异步操作**：对外部回调（网络请求、JSON 解析等）使用 `try/catch` 包裹，保证组件稳定性。
3. **业务错误**：优先使用返回值（如 `UploadResult`）或枚举（如 `EmptyDataType`）表达错误，而非抛出异常。
4. **用户反馈**：通过主题色（`theme.colorScheme.error`）和预置文案向用户清晰传达错误信息。
5. **避免硬崩溃**：不依赖 `throw Exception` 作为主要错误传播手段，确保组件在异常情况下仍能正常降级。
