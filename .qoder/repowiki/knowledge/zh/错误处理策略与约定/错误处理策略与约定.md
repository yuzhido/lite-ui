该 Flutter UI 组件库采用**结果对象 + 回调状态**的轻量级错误处理方式，未定义统一的异常类型或全局错误中间件。具体策略如下：

### 1. 网络/上传错误：`UploadResult` 结果对象
- `file_upload/model/upload_config.dart` 中定义 `UploadResult.success()` / `UploadResult.failure(error)` 工厂方法，通过 `success` 布尔字段区分成功与失败，错误信息以 `String? error` 传递。
- `upload_service.dart` 使用 `try/catch` 捕获 `SocketException`、`HttpException` 等，统一转为 `UploadResult.failure` 返回，不抛出异常。
- `upload_controller.dart` 在重试循环中调用 `validateResult` 业务校验，失败时通过 `_onFileStatusChanged(id, UploadStatus.failed)` 回调通知上层。

### 2. 表单验证错误：字符串消息 + FormField 集成
- `input_text/utils/valid_rules.dart` 的校验函数（如 `required`、`phone`、`email`）返回 `String?`，`null` 表示通过，非空字符串即为错误提示文案。
- `dropdown_choose.dart` 通过 `FormFieldState.errorText` 和 `LiteUITheme.of(context).errorColor` 渲染错误文本，颜色来自主题。
- 校验规则通过 `ValidRules.compose` 组合执行，返回第一个失败的消息。

### 3. UI 层错误展示：枚举驱动的空状态与弹窗图标
- `empty_data/models/index.dart` 定义 `EmptyDataType.error`、`noNetwork`、`noPermission` 等场景枚举，每种类型对应预设标题、描述、图标和配色。
- `dialog_action/models/index.dart` 提供 `DialogPresetIcon.error` 等预设图标，配合 `theme.colorScheme.error` 红色主题色统一视觉。

### 4. 调试与日志
- 所有关键路径使用 `debugPrint` 输出结构化日志（如 `[UploadController] 上传失败: id=$id, error=${result?.error}`），便于开发阶段排查。

### 开发者约定
- **不要抛异常**：I/O 和网络操作一律返回 `UploadResult` 或通过回调上报状态。
- **校验函数返回 `String?`**：空表示通过，非空即错误文案。
- **UI 错误走主题色**：错误文本使用 `LiteUITheme.of(context).errorColor`，保持视觉一致。
- **无全局错误处理器**：每个组件自行处理错误并向上层回调，不存在 try-catch 顶层拦截。
